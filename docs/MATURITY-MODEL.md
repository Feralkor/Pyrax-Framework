# Pyrax Maturity Model

## Purpose

The Maturity Model provides a common language for how far a solution has progressed from discovery to closed-loop intelligence.

## Levels

### P0 — Discovery
The organization/problem is being mapped. No production claims.

### P1 — Truth Mapped
Sources, semantics, grain and Evidence are sufficiently mapped for a bounded use case.

### P2 — Operational State
The solution reconstructs operational state with quality and reconciliation controls.

### P3 — Assisted Intelligence
Signals and constrained recommendations support human decisions.

### P4 — Predictive Operations
The solution anticipates future pressure/risk and can evaluate scenarios before action.

### P5 — Closed-loop Intelligence
Outcomes and Operational Memory feed a governed improvement loop; automation, if any, is separately authorized and controlled.

## Rules

1. Levels are cumulative; no level may skip unresolved prerequisites.
2. Maturity is not the same as production readiness. A product may be production-ready at P2 or P3 for its intended scope.
3. Higher maturity is not always better; it must match business value and risk.
4. P4 does not require heavy ML. Deterministic anticipation and scenario projection can qualify when validated for the use case.
5. P5 requires outcome capture and a governed feedback loop, not merely historical storage.

## Use

The model can be used in discovery, architecture reviews, roadmaps, consulting assessments and product communication.
